# Phase 2B implementation contract

This explicitly supersedes ADR-004's prohibition on audit-start tools at the user's Phase 2B request. Five tools are exposed: list_workspaces, get_workspace_summary, start_audit, get_audit_status and get_audit_report. Core audit semantics remain unchanged; no shell, generic file reader, repository registration or provider execution is exposed.

Each standalone `audit-host mcp PROFILE` process handles one stdio connection and every registered workspace in that profile. Up to eight connections can share a profile, including Claude internal sessions and Codex. Per-session control sockets, leases, grants and journals prevent authority mixing; registry and immutable report stores remain shared. A profile-wide audit lease serializes MCP audit workers. Its private Unix control socket connects the existing desktop to live permissions and consent. Closing the desktop does not terminate the gateway; closing the host stdio session does. No public HTTP listener or automatic tunnel is created.

A workspace capability grant separately authorizes discovery/summary metadata, audit requests and report publication requests. All default false. The concrete stdio session, not a claimed client name, owns authority. Scope controls include the session_id displayed at confirmation, so a gateway restart rejects stale grant dialogs. Discovery reveals the workspace name only after explicit approval. Each audit requires a separate immutable request approval for its exact workspace and commit. Each report transmission requires preview/approval of an immutable bounded projection. No raw source, paths, model prose or conversation content is included by default. A revoked epoch invalidates queued/executing operations and frozen report approvals; regranting never resurrects them.

The Task Brief is a deterministic template over validated tool arguments. Received user context is optional, bounded, and represented in stored records by byte length and SHA-256 only. It is never a reconstructed transcript. The received-payload display is explicitly redacted and the digest covers canonical validated arguments, not a claim to preserve original JSON-RPC wire bytes. The outbound preview/digest covers the exact structured tool-result data, not transport envelopes. It is assembled from an actually validated core report. Approvals never authorize broader filesystem access.

Each session retains at most 16 briefs with 24-hour retention; grants are session-only and restart defaults deny. Completion/error/revocation traces contain fixed event labels, identifiers and status, not arbitrary exception or source text. Expired records are removed while the gateway runs and at next startup; stopped processes cannot erase records on schedule. Old approvals never regain authority; deleting local records cannot recall data already delivered to a host. The host/provider boundary is visible at grant and transmission consent.

All authorization transitions and response construction are serialized. The `released` status records commitment to the MCP transport, not host/provider receipt. A response already committed under the authorization lock precedes a later revoke; no claim can revoke bytes already sent. Audit subprocesses are fixed self-executables with 10 CPU/15 wall-second limits, and are killed on revocation, gateway shutdown or timeout. Terminal state never implies success without a validated scoped report. Existing packed repositories remain denied pending a separately verified bounded reader.


## Wire contract and bounds

All tools accept JSON objects with unknown fields denied. Responses contain `ok`, a stable error `code`, and tool-specific `data`; both text and structuredContent carry the same envelope. Tool discovery advertises explicit input/output JSON schemas. `list_workspaces` takes cursor 0..64 and limit 1..20 (defaults 0/10); it returns only granted opaque IDs, names capped at 80 characters, and next_cursor. `get_workspace_summary` takes workspace_id and returns bounded validated-run counts and policy labels. Listing stops at 1,000 entries, 64 MiB cumulative report bytes or the cooperative deadline rather than implying a complete count.

`start_audit` takes workspace_id, full 40-hex commit, optional explicitly supplied task_context (512 UTF-8 bytes), and optional request_id for retrying the exact arguments. Initial calls return a pending request ID; retry returns consent/status/execution_id. `get_audit_status` takes workspace_id/execution_id and returns status/report_id. `get_audit_report` takes workspace_id/run_id and optionally request_id: initial calls return pending consent; a single approved retry releases the frozen projection. It includes commit/manifest identity, counts, capture time and honest execution/analysis statuses; it deliberately excludes evidence excerpts, paths and arbitrary findings prose. This is not the full locally stored report.

Canonical argument hashes preserve the validated values actually received, excluding the retry request_id; redacted display objects are separate. They do not preserve whitespace/order from the incoming JSON-RPC frame. A missing task_context is not invented. Read-only metadata/status responses contain no context and are not Task Briefs; the retained journal covers audit/publication consent transitions, not every security event. Raw rejected payloads are never logged. Report release consumes consent before response construction and journals that decision; transport failure requires a new publication request because delivery is unknown.

Stdio framing is capped at 64 KiB, tool arguments at 4 KiB, private control messages at 64 KiB, and retained records at 16/24 hours. Malformed JSON or oversized frames close the session before rmcp parsing. A bounded duplex buffer applies ingress backpressure. There is at most one active MCP audit worker per profile during normal operation; there is no unbounded execution queue. These limits do not claim denial-of-service protection against a compromised owner account.

The profile and control socket are owner-only, not authenticated multi-user services. A process with the same OS account can act as the local operator; a claimed MCP client name has no authorization weight. Registry writes remain under the existing exclusive desktop lock; fresh read-only Core Workspace handles allow discovery of later registrations without taking that writer lock. Core snapshot reads and writes use cap-std 4.0.3 directory capabilities, and gateway workers compare approved root/Git inode identity on opened handles. The existing Core evidence and report schema is unchanged. The gateway journal is private atomic JSON, not an encrypted or tamper-proof log. Failed consent journal persistence releases no data; a control-persistence failure revokes all in-memory grants. Terminal trace persistence is retried on subsequent activity; a crash can leave an interrupted trace, never a reconstructed success.

A worker stdin lease exits on parent pipe EOF, including gateway death; normal shutdown/revocation/timeout kill and reap the child. CPU time is 10 seconds, wall time 15 seconds. Desktop in-process audits retain their Phase 2A cooperative limits and do not inherit this gateway watchdog. Packed objects, linked worktrees and external object stores remain denied. No HTTP/OAuth service, tunnel provisioning, provider adapter, remote execution, conversation-history retrieval, or host extension packaging is implemented.


## Multi-connection compatibility correction — 2026-11-09

The actual Claude log demonstrated a successful primary initialize/discovery followed by failing Cowork/Code subprocesses. A profile-wide singleton rejected legitimate host execution lanes, even without Codex. The implementation now permits eight independently authorized stdio processes and shares only Core registry/report services. No central broker, second audit engine or new network listener was added. A short owner-private `.g/<session-key>/` directory holds each live lease, control socket and journal; the full random session UUID remains the authority identity and is checked when routing. A 12-hex filesystem key keeps the default macOS socket path within Unix limits; collisions fail closed. Startup registration is serialized to enforce the cap. Inactive state is cleaned after 24 hours at startup; capacity cleanup prunes oldest inactive entries when approaching the 256-entry scan bound. Live state is never removed by that cleanup.

Desktop control replies include live `{session_id, client}` summaries. Explicit `for_session` routing selects a full UUID; grants still carry the same session UUID. Ambiguous mutation without a selected connection is denied. A disconnected selection remains stopped with no grants, while other live connections remain selectable. It never falls back to authorizing a different connection. Active journals are isolated; bounded inactive history can be shown as historical records after restart but cannot restore authority or execution status access for another session. Revocation and shutdown affect only the selected process; the shared audit lease prevents ordinary concurrent MCP execution. Existing desktop audits retain their separate cooperative limits.

The legacy root `.gateway.lock` and `gateway.sock` are not deleted or bypassed. Existing running binaries must be restarted once to load the fix. Known startup failures now return fixed diagnostic codes for unavailable/invalid profiles, session capacity/startup contention, unsafe state or local socket failure; raw repository paths and request contents remain omitted. Actual fixed-binary Claude/Codex host reconnection still needs an operator restart; synthetic concurrent protocol tests do not establish every host feature.
