# Technology compatibility verification

Checked **2026-11-06** against the official sources linked below. “Confirmed” means documented capability, not a successful Orven build or live integration. This original source review was documentation-only. Subsequent Phase 1 builds and tests are recorded in [the validation receipt](phase-1.md); remaining integrations below are still unverified. Branch manifests are observations of moving branches, not verified published release pins. Recheck before choosing and locking dependencies.

| Area | Confirmed from official documentation/source | Architectural consequence / remaining proof |

| Tauri 2 | Tauri supports a Rust backend with WebView UI and platform-specific prerequisites. The inspected official development manifests declare Tauri `2.12.5`, edition 2024 and Rust `1.90`. | rmcp | The official Rust MCP SDK uses Tokio. Its inspected main workspace declares `3.9.0`, edition 2024 and Rust `1.88`; features include `transport-io` and `transport-streamable-http-server`. [README](https://github.com/modelcontextprotocol/rust-sdk), [workspace](https://raw.githubusercontent.com/modelcontextprotocol/rust-sdk/main/Cargo.toml), [crate features](https://raw.githubusercontent.com/modelcontextprotocol/rust-sdk/main/crates/rmcp/Cargo.toml). | Rust/Tauri/rmcp are compatible architectural building blocks; no combined dependency-resolution or runtime proof exists yet. Keep rmcp in audit-host, Tauri in the desktop shell, and core independent of both. Pin published releases and minimal features in Phase 1. |
| MCP revision | The current specification resolves to `2026-07-28`; the SDK README documents support for it and older revisions. Modern requests differ from older initialize/session-based flows. [Transports](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports), [version compatibility](https://modelcontextprotocol.io/specification/2026-07-28/basic/versioning), [SDK protocol notes](https://raw.githubusercontent.com/modelcontextprotocol/rust-sdk/main/README.md). | Use SDK negotiation/compatibility behavior; record actual host protocol versions. Do not implement a custom handshake or presume every host uses the newest revision. Initial tools need no modern-only tasks, sampling or subscriptions. |
| HTTP transport and auth | Streamable HTTP and stdio are standard bindings. HTTP security includes Origin checks, restricted local binding and authentication; protected MCP resources have OAuth authorization/discovery and audience-bound token requirements. [HTTP binding](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http), [authorization](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization). | Implement authentication and report authorization outside/around transport handling; SDK transport support is not proof of a secure deployment. Validate current and negotiated older paths. Do not build the superseded standalone HTTP+SSE transport. |

The compatible toolchain direction is a documentation-based inference from the manifests. Exact release availability, transitive dependency compatibility, desktop event-loop integration and effective MSRV remain unverified until a locked build. Do not use historical Rust minimums from older tutorials as current pins.

## Host and adapter matrix

| Surface | Confirmed path | Limits and Orven status |

A Mac-hosted tunnel cannot serve a sleeping Mac. |

[Build/deploy MCP](https://developers.openai.com/plugins/build/mcp-server). | A public source repository does not imply submission, approval or hosting. Plain model-readable MCP tools are the initial target; rich UI and public directory distribution are deferred. |
| Claude Desktop local | Official guidance demonstrates client-launched local MCP processes. [Local server guide](https://modelcontextprotocol.io/docs/2026-07-28/develop/connect-local-servers). | Plan a native Rust stdio binary; Node.js requirements in example filesystem servers are not a requirement of MCP itself. | Claude remote connectors | Connections originate from Anthropic infrastructure, including when configured in Desktop; endpoint must be cloud-reachable. [Remote connector guidance](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp). | Use authenticated HTTPS for the shared remote route. | Optional Codex adapter | App Server supports subprocess stdio with newline-delimited JSON and its own JSON-RPC-based protocol, omitting the usual `jsonrpc` field. No official native Rust Agent SDK is established by these sources. JSON output and bare mode are not sandbox guarantees; exact flags/version, credentials and confinement require tests. |

## Required implementation receipts

1. Exact stable compiler, selected published crate versions/features, lockfile, OS/architecture, build and protocol-test results. Do not claim the branch versions above are a tested dependency set.
2. Each selected host's version/date, account/workspace policy, transport, negotiated protocol, advertised schemas and valid/invalid tool-call results. Test all three report tools plus unauthorized evidence access and partial/empty data. A protocol inspector is useful but does not replace actual ChatGPT/Claude receipts.
3. For HTTP: token discovery/validation, wrong issuer/audience/scope, expiry/revocation, Origin/Host handling, size limits and unauthorized report IDs. Keep any SDK/proxy caches partitioned by principal and scope; stale/unavailable state must remain visible.
4. For native UI, runner and optional adapters: separate receipts for IPC denials, repository non-mutation, process isolation, provider egress limits, offline behavior and failed dependencies. Native packaging, signing and public distribution remain distinct release gates.
